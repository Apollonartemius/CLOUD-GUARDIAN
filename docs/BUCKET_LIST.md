| 7 | JWT rotation + refresh tokens | **DONE** | Medium | Small | `shared/auth.py` (synced to all 5 services): rotating key support (`JWT_PREVIOUS_SECRETS` verification) + full refresh-token life cycle — `POST /auth/login` returns a 6h `access` token *and* a 7d `refresh_token`; `POST /auth/refresh` (public) validates `typ=refresh`, rotates to a brand-new pair, and refresh tokens are rejected as Bearer on protected routes (typing `typ: access|refresh` + `jti` in the payload). Verified live: login → refresh → new pair, refresh-as-Bearer 401 vs access 200 on `/incidents/current`. 4 tests: login fields, access/refresh separation, rotation, garbage + access-token rejection |
| 8 | API versioning (`/v1/...`) | **DONE** | Low | Small | Shared `api_versioning.py` (copied to all 5 platform services) ASGI-rewrites `/v1/<path>` → `/<path>` with `root_path` recorded, so every route is versioned without touching handlers; plain `/` keeps working.
